# Sigil documentation

The public product documentation for **Sigil** (by Tophhie Cloud), the centrally
managed email signature platform for Microsoft 365 and Outlook.

Built with [Astro](https://astro.build) and
[Starlight](https://starlight.astro.build), deployed to Cloudflare Workers.

| Repo | Role |
| --- | --- |
| `sigil-documentation` | This repo. Public docs |
| `outlook-signature-worker` | Signature API and admin portal, `portal.usesigil.app` |
| `outlook-signature-addin` | The Outlook add-in and the Worker serving it, `static.usesigil.app` |

## Layout

```
src/
├── assets/            brand mark used by the site header and hero
├── content/docs/      every page, one directory per sidebar section
│   ├── start/         what Sigil is, how it works, quickstart, rollout
│   ├── deploy/        requirements, consent, permissions, add-in deployment
│   ├── signatures/    templates, editors, placeholders, publishing, versions
│   ├── targeting/     assignment rules, banners, footers
│   ├── monitoring/    activity, attribute coverage, link clicks, change log
│   ├── admin/         users and roles, billing, checklist, test email
│   ├── users/         pages written for everyone at a customer, not for admins
│   ├── partners/      the MSP programme
│   ├── security/      security model, privacy, compliance, infrastructure
│   └── reference/     roles matrix, limits, glossary, API, FAQ
└── styles/sigil.css   brand theming over Starlight's tokens
```

Sidebar groups are declared in `astro.config.mjs` and their contents are
autogenerated per directory. Ordering within a group comes from `sidebar.order`
in each page's frontmatter, so adding a page means adding a file and giving it an
order.

## Branding

The mark in `src/assets/sigil-mark.png` and the favicon in `public/` are copied
from the portal's own assets (`server/assets/` in `outlook-signature-worker`).
Copy them across again rather than editing them here.

Brand pink is `#E8005A`, and the dark surfaces are the Tophhie Cloud design
system's `#121212` and `#1C1C1E`. `src/styles/sigil.css` maps those onto
Starlight's accent and grey scales.

## Writing style

Pages follow the humanizer conventions: sentence case headings, no em or en
dashes, straight quotes, no emoji, minimal bold, and tables rather than
bolded-term lists for reference content. Prefer plain statements over
promotional framing.

Product claims should be traceable to the source repos. `outlook-signature-worker`
carries `docs/PRODUCT-OVERVIEW.md` and a long `README.md`; the add-in repo's
`README.md` covers client behaviour and the constraints Outlook imposes.

## Commands

| Command | Action |
| --- | --- |
| `npm install` | Install dependencies |
| `npm run dev` | Local dev server on `localhost:4321` |
| `npm run build` | Build to `./dist/` |
| `npm run preview` | Build, then preview locally |
| `npm run deploy` | Build, then `wrangler deploy` |
| `npm run cf-typegen` | Regenerate Worker types after changing bindings |

When starting the dev server from an agent session, use `astro dev --background`
and manage it with `astro dev stop`, `astro dev status` and `astro dev logs`.
